# 650～655 自动录包服务器测试流程

假设整个包已放在 `/home/dnt/ws_ros2_rtg/src/rtg_auto_bag_recorder`，ROS 2 为 Humble。
以下以 655 的既有 bag 为例。测试其他编号时，将配置文件改为相应的
`recorder_650.yaml`～`recorder_654.yaml`，并使用包含对应四路雷达及 PLC 的 bag。
四个终端按顺序操作；不要将 `ros2 bag play -p` 改为循环播放。

## 终端 1：核对源码、编译

```bash
cd /home/dnt/ws_ros2_rtg
source /opt/ros/humble/setup.bash
colcon list --packages-select rtg_auto_bag_recorder
grep -n 'detected_truck_type_ == required_truck_type_' src/rtg_auto_bag_recorder/src/auto_bag_recorder_node.cpp
ls src/rtg_auto_bag_recorder/config/recorder_65*.yaml
ls src/rtg_auto_bag_recorder/src/format_ros_log_time.cpp
colcon build --packages-select rtg_auto_bag_recorder
```

`colcon list` 必须指向刚上传的包；构建结果应为 `1 package finished`。
录包节点与 C++ 时间显示程序都会安装到该包的 `lib/rtg_auto_bag_recorder`。

## 终端 2：暂停播放 655 原始 bag

```bash
cd /home/dnt/ws_ros2_rtg
source /opt/ros/humble/setup.bash
source install/setup.bash
export TZ=Asia/Shanghai
set -o pipefail
ros2 bag play "/mnt/win_share/Data_Storage/研发/HIT/防吊起/655_2026_06_23_ATL1" -p --topics \
  /livox/lidar_3GGDN5400200311 \
  /livox/lidar_3GGDN4V00216211 \
  /livox/lidar_3GGDN6900226151 \
  /livox/lidar_3GGDN4800200341 \
  /rtg/plc_topic_35 2>&1 | /home/dnt/ws_ros2_rtg/install/rtg_auto_bag_recorder/lib/rtg_auto_bag_recorder/format_ros_log_time
```

此时保持播放器运行，不按空格。启动录包节点前，四路雷达必须有发布者。

## 终端 3：用 655 配置启动录包

```bash
cd /home/dnt/ws_ros2_rtg
source /opt/ros/humble/setup.bash
source install/setup.bash
export TZ=Asia/Shanghai
set -o pipefail
ros2 launch rtg_auto_bag_recorder auto_bag_recorder.launch.py config:=/home/dnt/ws_ros2_rtg/install/rtg_auto_bag_recorder/share/rtg_auto_bag_recorder/config/recorder_655.yaml 2>&1 | /home/dnt/ws_ros2_rtg/install/rtg_auto_bag_recorder/lib/rtg_auto_bag_recorder/format_ros_log_time
```

先核对日志中列出的四路雷达与 655 配置一致，并出现“雷达 Topic 检查通过”。
`config:=...` 必须与 `ros2 launch` 在同一命令中；不传 `config` 会报错。

## 终端 4：补发任务和方向为 none 的集卡检测

```bash
cd /home/dnt/ws_ros2_rtg
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 topic pub /rtg/task_exec_status rtg_algorithm_interfaces/msg/ExecStatusMsg "{truck_type: 'OTK', action_type: 2}" --once
ros2 topic pub /algl/TruckDetectMsg rtg_algorithm_interfaces/msg/TruckDetectMsg "{region_has_truck: true, truck_direction: {result: 'none'}, truck_type: {result: 'OTK'}}" --once
```

这两条只用于回放测试，不是现场自动运行所需的操作。

## 回到终端 2：开始播放并核验

按一次空格继续播放。终端 3 应先出现“下一次录包已预热”，随后在抓箱闭锁且
`trolley_pos <= 1.5 m` 时出现 `Resuming recording.`、“开始录包，当前时间=…”；
到开锁或 `hoist_height >= 10.0 m` 时出现“录包已结束，当前时间=…”。
`Opened database` 和 `Waiting for recording` 仅代表预热，不能算开始录制。

记录“录包已结束”日志中的目录，再检查落盘数据：

```bash
cd /home/dnt/ws_ros2_rtg
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 bag info '/home/dnt/ws_ros2_rtg/ros_bag/此处替换为已结束的bag目录名'
```

结果应列出四路雷达及 PLC；实际消息数以 `ros2 bag info` 为准。预热的下一包
不是本次完成的录制。结束测试时，先停止播放，再在终端 3 按 Ctrl+C 正常退出。

终端 2、3 的日志经 C++ 显示程序处理后，ROS 方括号中的 Unix 秒显示为北京时间，
保留原始九位小数。程序在预热、开始、结束日志中也会另显示北京时间。
转换只影响终端输出，不修改 rosbag 消息时间戳或 ROS 原始日志文件。
