# 来源区分验收

以下需要隔离 ROS_DOMAIN_ID 和实际 ROS2 环境；本地纯 C++ 测试不能替代。

创建持续存在的 A/B 发布端，均发布 SafetyDetectMsg 至 /algl/GantryColDetMsg：
A 使用 gantry_collision_detect_frame，B 使用 gantry_side_truck_detect_frame。

1. B 发布区域1/3、7/8的报警或正常消息：均不能触发或续期，也不入缓存和包。
2. A 发布区域1报警：仅left触发，但包应包含四路雷达、PLC和四区正确来源消息。
3. A 在第0、3、6秒发送区域1报警：left应在第11秒关闭。B消息、空frame_id、无效距离和正常消息不能续期。
4. A 仅发送一次区域2报警后销毁发布者，B保持存在：right应在最后报警后约5秒关闭，同时报告防撞来源离线。
5. 重建A，不发送区域4解除；静默超过5秒后发送区域2报警，应可开新right包。录制不依赖两区解除。
6. A的区域7/8不能触发或续期；A的区域2消息可以进入left包，但只能续期right。
7. 每秒发送本组报警，每包触发后120秒应关闭；后续报警立即触发新包，补写前2秒缓存，不等待静默或解除。核对新包独立计时、六话题及缓存覆盖。

检查DB3实际六话题、帧号、起止时间、触发消息及关闭后文件不再增长。frame_id是业务标记，不是身份认证；无法解决多个节点冒用相同来源与区域的问题。
